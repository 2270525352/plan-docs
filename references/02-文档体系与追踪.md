# 文档体系与追踪

## 规范树

所有新输出写入 `docs/plan-docs/`。根级 `AGENTS.md` 保存长期规则，`CURRENT_STATE.md` 保存动态状态。

```text
00-source       用户原话、AI 推断与事实查证
01-requirements 访谈、开放问题、AI 可读需求、追踪矩阵
02-architecture 总体架构、接口契约
03-product      项目说明、产品/交互索引、术语、数据、API、测试、原型、递归 modules
04-tasks        总任务、I/O 合同注册表、依赖/并行计划、各 AI 任务文档
05-execution    环境分工、执行反馈、三种执行模式、current-task.json
06-reviews      六代理提示词、报告汇总、偏离报告、自动模式门禁
07-goals        门禁通过后生成的最终执行提示词
08-automation   Codex App 定时审查提示词与设置说明
09-git          Git 纪律和 checkpoint
10-guards       护栏说明
```

模板唯一来源是 `templates/project-tree/`；模块与按钮叶子使用 `templates/fragments/`。不要在 references 中复制整份模板。

## 完整追踪链

每条链都必须可双向核对：

```text
U-* → REQ-* → MOD-*/INT-* → ADR-*/API-* → TASK-* → AI 子任务
    → TEST-* → REV-* → FB-* → CP-*/commit
```

`01-requirements/需求追踪矩阵.md` 记录主链。架构、产品、任务、测试和审查文档在各自条目内引用上游 ID。没有来源的内容只能标记为假设或开放问题。

## 产品与交互树

- `产品及交互索引.md` 是模块层级和横向依赖的事实来源；结构变更先更新索引，再更新节点文档。
- 目录层级表达父子关系；`parent`、`children`、`dependencies` 字段表达可机读关系。
- 一个按钮、输入字段、状态转换、错误反馈或微小动作只要有独立行为，即建立叶子文档。
- 叶子至少记录：`interaction_id`、来源需求/原话、场景、触发、前置条件、逐步逻辑、状态、边界、数据读写、权限、可访问性、埋点、错误反馈、测试引用。
- 原型是已确认交互文档的可视化镜像。缺少行为定义时回到产品文档，不在原型中创作新需求。

## 架构与接口

记录系统边界、组件、数据流、信任边界、依赖、扩展点、失败与恢复、观测、迁移和回滚。每个接口固定：

```text
interface_id
owners
consumer_tasks
producer_tasks
request_or_input_schema
response_or_output_schema
errors
compatibility
versioning
verification
change_lock
```

共享接口冻结后，只有协调者能先更新接口契约并重新审查，再解除相关任务阻塞。

## 原子任务判定

一个任务应只有一个主要结果，并能独立验证。以下情况继续拆分：

- 触碰多个无依赖文件组；
- 同时改变 schema 和多个消费者；
- 包含“以及”“顺便”“全部优化”等不可界定动作；
- 验证命令不能清晰判断单个结果；
- 不同 AI 可以在不共享写入文件的前提下独立完成。

任务字段使用 SKILL.md 指定的完整集合。`allowed_scope` 和 `forbidden_scope` 使用明确相对路径；禁止只写“相关文件”。`input_contracts` 与 `output_contracts` 使用稳定的文档、schema、接口或制品 ID；存在依赖时，下游输入必须能对应上游输出。`merge_order` 与 `conflict_resolution` 必须给出明确动作；确实不适用时写 `N/A: <原因>`，不能留空。

总任务是唯一任务事实来源。各 AI 任务文档里的任务合同必须逐字段复制，不能只复制 `task_id`。每个 AI 文件还声明 `assignment_status: active | none`；`none` 必须配具体 `no_tasks_reason`，以便单 AI 模式明确表达未分配角色。

`任务合同注册表.md` 是所有 `CONTRACT-*` 的唯一事实来源。每条合同必须声明
`producer_tasks`、`consumer_tasks`、`artifact_refs`、`required_content`、
`completion_condition`、`verification`、`compatibility` 和 `status: frozen`。任务引用与
注册表的生产/消费关系必须双向一致。

## CURRENT_STATE 语义

动态状态必须包含：当前阶段、当前任务、当前负责人、锁定文件、已完成工作、待用户决定、各 AI 状态、最近 commit、阻塞项、下一步。

- 写最终文件前先取得锁并更新状态；
- 写入前再次读取目标文件最新版本；
- 完成、阻塞、交接、review、commit 后立即更新；
- 不把长篇历史塞入 snapshot；追加简短状态日志；
- 当前状态有冲突时以磁盘最新内容为准并停止竞争写入。
