# 老项目与兼容迁移

## 先只读理解

老项目先读取：

- 根规则、当前状态、README 和已有规划文档；
- 依赖/构建配置、入口、目录和主要模块；
- 数据模型、接口、测试、部署和 Git 状态；
- 现有 `docs/`、hooks、Claude settings 和自动化配置。

区分三类内容：

1. 代码或文档可直接证明的现状；
2. 用户明确确认的目标；
3. AI 推断或待核实事实。

第三类只能写入 `AI推断与事实查证.md` 或 `开放问题.md`。

## 旧版 plan-docs 映射

旧输出不移动、不删除、不覆盖。新树使用引用或复制后确认的迁移方式：

| 旧路径 | 新路径 |
|---|---|
| `docs/用户原话.md` | 保持原文件；新记录写入 `docs/plan-docs/00-source/用户原话.md`，并在追踪矩阵标注 legacy 来源 |
| `docs/00-项目说明书.md` | `03-product/项目说明书.md` |
| `docs/01-需求文档.md` | `01-requirements/AI可读需求文档.md` |
| `docs/02-架构文档.md` | `02-architecture/总体架构.md` |

| `docs/04-开发追踪.md` | `04-tasks/任务依赖与并行计划.md` + `CURRENT_STATE.md` |
| `docs/05-术语表.md` | `03-product/术语表.md` |
| `docs/06-数据字典.md` | `03-product/数据字典.md` |

| `docs/modules/` | `03-product/modules/` |

## 非破坏迁移步骤

1. 记录旧文件清单、hash 和 Git 状态；
2. 运行 bootstrap，只合并根协调文件；
3. 创建新目录和空白规范模板，不覆盖同名内容；
4. 建立 `LEGACY-*` 来源映射；
5. 把旧内容转写到新 AI 可读字段时标记“迁移草稿”，逐项让用户确认；
6. 确认后更新追踪矩阵；旧文件保持原位；
7. 禁止建立含混的双重事实来源：新索引明确旧文件为 `legacy/read-only`；
8. 迁移通过审查后再决定是否归档旧路径；未获授权不移动或删除。

## 原话兼容

不要为了补 `U-*` 编号修改旧原话。对旧段落生成外部稳定映射，例如：

```text
legacy_id: LEGACY-U-20260614-01
source_path: docs/用户原话.md
source_anchor: 2026-06-14 / 第 1 条用户发言
content_hash:
mapped_requirements:
```

映射放在 `需求追踪矩阵.md`，不放进用户原话文件。

## 旧 hooks/settings

- 不修改无法安全合并的自定义 hook；
- 不把现有 `core.hooksPath` 改为新路径；
- JSON settings 只追加去重后的 Plan Docs hook 条目；
- 冲突时保留原配置，记录手动串联步骤和门禁阻塞；
- 所有安装前备份应可识别、可恢复；卸载只删除 Plan Docs 自有项。
