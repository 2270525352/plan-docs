# plan-docs 技能设计

本文件记录技能自身的当前设计。历史用户原话保存在 `用户原话.md`，不得修改。

## 定位

在项目开发前，把用户原始想法收敛成需求对齐、结构完整、可审查、可分工、可被多个 AI 精确执行的文档树；审查通过后，再生成 Claude、Codex、Reviewer、CCB、单 AI CLI 和 Codex App 自动化所需的执行提示词。

## 产品规划层

plan-docs 的主体仍是：

- 用户原话留存；
- PM 式需求讨论和实用性判断；
- 项目说明、AI 可读需求和架构/接口；
- 可无限递归的模块与子模块树；
- 按钮、字段、状态和错误反馈级叶子交互文档；
- 高保真 HTML/CSS/JS 可交互原型；
- 术语、数据字典、API 和测试用例；
- 根据模块/接口依赖推导开发顺序。

产品索引是模块父子关系和横向依赖的结构事实来源。每个节点使用稳定 ID，并向上追溯用户原话/需求，向下关联任务、测试、审查和 commit。

## 执行控制层

新增的执行层包含：

- 项目根 `AGENTS.md` 长期规则与 `CURRENT_STATE.md` 动态交接；
- CCB、多窗口和单 AI CLI 三种执行环境；
- 一个协调者和最终合并权威，但允许多个 AI 成为不重叠任务的正式 owner；
- 文件写锁、共享接口锁、依赖、输入输出、合并顺序和冲突处理；
- 总任务先行，再拆 Claude、Codex、Reviewer（Claude）和可选 OpenCode 任务；
- 只追加的执行反馈和任务级 Git checkpoint；
- 六个独立 Reviewer、汇总、修订和复审；
- 自动模式门禁；
- 通过能力检测生成 `/goal` 或普通提示词；
- Codex App 每半小时独立偏离审查提示词；
- Claude hooks 和 Git hooks 的确定性护栏。

## 真相源与追踪

用户原话文件只保存原话和稳定 ID。AI 推断、事实查证、解释和结论进入单独文件。

```text
U-* → REQ-* → MOD-*/INT-* → ADR-*/API-* → TASK-*
→ TEST-* → REV-* → FB-* → CP-*/commit
```

ID 发布后不可换绑。未确认的内容只能是开放问题或推断，不能伪装成需求。

## 门禁

需求、任务和分工确认前不实现。最终执行提示词只有在：

- 六代理无 RED；
- 无未处理 P0/P1 YELLOW；
- 需求、任务、验收和追踪完整；
- 负责人、范围、验证、写锁和停止条件完整；
- 无文件/接口冲突；
- 用户确认最终规划、分工和 Git 策略；

时才生成。

## 兼容性

旧版 plan-docs 输出保持原位，通过 legacy 映射迁移到 `docs/plan-docs/`。不修改旧用户原话，不覆盖现有 `AGENTS.md`、`CURRENT_STATE.md`、hooks、Claude settings 或用户 Git 改动。
